Benchmark · 28 October 2026

13 DNS resolvers, measured. Quad9 wins from here.

Every web request starts with a DNS lookup. I timed 960 plain lookups and 576 encrypted ones against Cloudflare, Google, Quad9 and ten others, then checked which ones validate DNSSEC, which ones leak your location, and what each one blocks. Quad9 was fastest, passed every check, and blocked 61% of live malware hosts on its default address.

What stands out

Eight resolvers land within 3.2 ms of each other on cached lookups, too close to feel. The differences that matter are below.

3

resolvers skip DNSSEC validation. Level3, Comodo and Yandex all returned an address for dnssec-failed.org, a domain whose signature is deliberately broken.

3

send the first 24 bits of your IP to every domain's servers: Google, OpenDNS and AdGuard. That helps CDNs pick a nearby server, and it tells every domain owner roughly where you are.

is OpenDNS's 90th percentile, against a 14.7 ms median. It has the slowest outliers of the fast group.

What they block

Method

Everything below comes from scripts/bench.py; the raw samples are in raw/.

  • Plain DNS. Raw UDP from Python with a 2 s timeout, 40 rounds. Each round shuffles the resolver order so network drift hits every resolver equally.
  • Cached. One of 15 popular domains, warmed into every resolver's cache first.
  • Cache miss. A fresh random 14-character name under one of 6 unsigned zones, unique per resolver per round. No resolver can reuse another's cache or synthesize the answer from DNSSEC records.
  • Encrypted (DoH). RFC 8484 GETs with curl, 16 on one connection, 3 times per endpoint. The first request includes TCP and TLS setup; "warm" is the median of the other 45.
  • Checks. dig against dnssec-failed.org (DNSSEC), a random .com name (NXDOMAIN), Google's and Akamai's whoami records (subnet leak), and a TLS connection on port 853 (DNS over TLS). No plain lookup timed out, and no resolver redirected a made-up name to an ad page.
  • Blocking. scripts/filtering.py samples up to 150 hosts per list, at most 10 per parent domain, keeping only ones Google or Cloudflare still resolve. Every resolver gets the same names at the same time; errors are re-asked once slowly, since Control D answers REFUSED when one client hits several of its addresses at once. A domain either reference lost during the run counts as taken down and is dropped (1 was). A block-page address must cover 3+ unrelated domains and sit on a different network than the real answers, so a resolver abroad that sees a different CDN edge doesn't count as blocking. Only hostnames were resolved; nothing was visited.
  • Re-run. The first encrypted pass was lost to a network drop partway through, so DoH was re-run on its own. The plain-DNS rounds were unaffected.
  • Limits. One machine, one network, one evening. Anycast routing means the order will differ from other places, so treat gaps under about 3 ms as noise. Blocking is one pass on one day's lists, and threat lists go stale within hours.
